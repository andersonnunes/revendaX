# ADR-0003: .NET 10 como stack

## Status
Aceito

## Contexto

A stack de implementação não era exigida pelo enunciado — precisava ser escolhida para este
trabalho individual. Critérios: familiaridade prévia com a stack, suporte de longo prazo (o
projeto é entregue e avaliado, não fica em manutenção contínua, mas ainda assim vale evitar
uma versão já descontinuada), e qualidade da integração com OpenID Connect/OAuth2 para falar
com o Keycloak (ADR-0001).

## Decisão

**.NET 10** (ASP.NET Core Web API, controllers) para `identity-api` e `vendas-api`.

- .NET 10 é a versão **LTS** mais recente da plataforma (suporte longo, ao contrário de uma
  versão STS intermediária).
- Suporte a OpenID Connect/OAuth2 via `Microsoft.AspNetCore.Authentication.JwtBearer` é
  maduro e nativo — sem biblioteca de terceiros para validar o JWT do Keycloak via JWKS.
- Geração de OpenAPI nativa (`Microsoft.AspNetCore.OpenApi`, desde o .NET 9) elimina a
  dependência de um gerador de terceiros para documentar a API (ver
  [ADR-0004](0004-scalar-em-vez-de-swagger.md)).

## Consequências

**Positivas:**
- Suporte de longo prazo — a solução não fica presa a uma versão que sai de suporte antes da
  avaliação/manutenção terminar.
- Tooling de contêiner oficial (`mcr.microsoft.com/dotnet/sdk:10.0` /
  `mcr.microsoft.com/dotnet/aspnet:10.0`) já disponível para os Dockerfiles multi-stage.

**Negativas / trade-offs aceitos:**
- É uma versão recente — bibliotecas de terceiros (ex.: clientes de Keycloak, pacotes de
  teste) podem demorar mais a publicar builds compatíveis; mitigado usando prioritariamente
  APIs nativas do ASP.NET Core em vez de wrappers de terceiros onde possível.
- Um primeiro esqueleto (US0) chegou a ser gerado com .NET 8 antes desta decisão, com 3
  serviços em vez de 2 — foi descartado junto da mudança para este repositório (`revendaX`)
  e será recriado direto em `net10.0`. Detalhes em `fase3/docs/refinamentos/US0-esqueleto-apis.md`,
  fora deste repositório.
